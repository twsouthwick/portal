# Portal Experience Specifications

These brownfield EARS specifications record behavior observed in the current
implementation. `[x]` means the behavior exists; it does not mean a test
currently cites the ID. The layout restoration adds implementation citations
for UX-009–011 and rendering regression coverage for UX-009 and UX-011.

- [x] **UX-001** When an authenticated user opens the portal home route, the application shall render site discovery through the interactive Blazor experience. Evidence: `Portal.Web/Components/Routes.razor:1-8`, `Portal.Web/Components/Pages/Home.razor:1-33`.
- [x] **UX-002** When the user supplies a search query or changes the site view mode, the UI shall filter or regroup the displayed site cards accordingly. Evidence: `Portal.Web/Components/SiteSearchBar.razor:1-53`, `Portal.Web/Components/SiteViewModeSelector.razor:1-56`, `Portal.Web/Components/SiteCategoryView.razor:1-43`, `Portal.Web/Components/SiteFrequencyView.razor:1-42`.
- [x] **UX-003** When browser information is available, the UI shall hide sites marked private when the browser is not in private mode and shall filter app options by supported platform. Evidence: `Portal.Web/Components/SiteProvider.razor:35-98`.
- [x] **UX-004** When an internal site is rendered with a remote-IP state, the site card shall be disabled. Evidence: `Portal.Web/Components/ConnectionState.razor:1-33`, `Portal.Web/Components/SiteCard.razor:43-56`.
- [x] **UX-005** When a user activates a site card, the UI shall attempt its configured app protocols and open the site's web URL if those attempts fail. Evidence: `Portal.Web/Components/SiteCard.razor:57-84`.
- [x] **UX-006** When a site has usage instructions, the UI shall make those instructions available through the usage modal. Evidence: `Portal.Web/Components/SiteCard.razor:25-37`, `Portal.Web/Components/UsageModal.razor:1-33`.
- [x] **UX-007** When the UI needs browser detection, app launching, or local-storage access, it shall use the browser-session abstraction backed by JavaScript interop. Evidence: `Portal.Web/Browser/IClientBrowserSession.cs:1-19`, `Portal.Web/Browser/JsClientBrowserSession.cs:1-163`.
- [x] **UX-008** When a user activates a platform-specific app-launch button and its protocol launch fails, the UI shall open the configured store destination as provided. The destination may be a URL or a store ID. Evidence: `Portal.Web/Components/SiteLauncher.razor:52-61`, `Portal.Web/Services/SiteInfo.cs:34-40`; test fixture with a bare store ID: `Portal.Web.Tests/KubernetesPortalProviderTests.cs:31-35`.
- [x] **UX-009** When site cards are displayed, each card shall fill its grid row, with a minimum height of 250px and launch actions aligned at the bottom; longer content shall grow the row without clipping. The grid shall retain its 24px gap and one, two, three, and four columns at its existing extra-small, small, medium, and large breakpoints. Evidence: `Portal.Web/Components/SiteCard.razor`, `Portal.Web/Components/SiteCard.razor.css`, `Portal.Web/Components/SiteGrid.razor`; rendering regression: `Portal.Web.Tests/PortalExperienceTests.cs`. Browser preview confirmed row filling and long-content growth; no automated viewport coverage is claimed.
- [x] **UX-010** When the portal header is displayed or the viewport changes size, its row shall grow to fit the title, view selector, and sign-out action without clipping them, including the stacked mobile layout. Evidence: `Portal.Web/Components/Layout/MainLayout.razor`, `Portal.Web/Components/Layout/MainLayout.razor.css`. The browser preview confirmed header fitting at the inspected viewport; mobile behavior lacks automated coverage.
- [x] **UX-011** When category and site headings are displayed, they shall use supported Fluent UI v5 typography, with category headings larger than site headings and site headings larger than body descriptions. Evidence: `Portal.Web/Components/SiteGrid.razor`, `Portal.Web/Components/SiteCard.razor`; rendering regression: `Portal.Web.Tests/PortalExperienceTests.cs`. Browser preview measured 24px category headings, 16px site headings, and 14px descriptions.
- [x] **UX-012** When the main or signed-out layout is displayed, the portal shall render a footer containing `Version {version}`, where `{version}` is Portal.Web's informational version with any `+` build metadata removed; the footer shall remain inside the visible viewport while content scrolls independently, with wrapped text and mobile safe-area insets not obscuring content. Evidence: layout Razor/CSS and `VersionFooter.razor.css`; browser checks at 320×640 and 800×600 with long content and wrapped version text. The main shell's CSS was checked with synthetic content; native safe-area verification remains pending.
- [x] **UX-013** When the portal home route is first displayed, the UI shall default to Categories regardless of a previously saved view mode, displaying alphabetically ordered category buttons with filtered site counts and no site cards, using `Other` for uncategorized sites. Selecting a category shall display only its sites with a Back to categories action; multi-category sites shall belong to each category. Search shall update membership and counts and return to categories if the selected category no longer exists. Navigation shall be keyboard-operable, focus the destination's Back control, and restore focus to the activating category button on return. Most Used shall remain available as an explicit view choice, and existing site launch and usage actions shall be unchanged. Evidence: `MainLayout.razor`, `SiteViewModeSelector.razor`, `SiteCategoryView.razor`; rendering and event regression: `Portal.Web.Tests/PortalExperienceTests.cs`.
